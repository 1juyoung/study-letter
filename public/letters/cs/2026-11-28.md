## 개념

웹 브라우저와 서버는 기본적으로 요청이 끝나면 이전 상태를 기억하지 않는 무상태(Stateless) 특징을 가지고 있어요. 이때 로그인 상태나 사용자 설정을 유지하기 위해 쿠키와 세션을 활용해요. 쿠키는 손님의 주머니에 넣어주는 '출입 도장'처럼 클라이언트에 텍스트 형태로 저장되는 데이터예요. 반면 세션은 가게 장부에 손님 정보를 적어두고 손님에게는 '열쇠 번호(세션 ID)'만 발급해 주는 방식으로, 데이터 본문은 서버 자원에 안전하게 저장돼요.

**핵심 정리**

- 쿠키는 클라이언트(브라우저)에 텍스트 형태로 저장되고, 세션은 서버 자원(메모리나 데이터베이스 등)에 저장돼요.
- 쿠키는 하나당 최대 4KB 크기 제한이 있고 현대 브라우저는 도메인당 수백 개까지 저장할 수 있으며, 세션은 서버 물리 자원의 한계에 영향을 받아요.
- 쿠키는 매 HTTP 요청마다 서버로 자동 전송되어 네트워크 성능에 영향을 줄 수 있으므로 용도에 맞게 써야 해요.
- Expires나 Max-Age 속성이 없는 쿠키는 세션 종료 시 삭제되는 세션 쿠키로 동작하고, 속성이 지정된 쿠키는 영구 쿠키로 지정된 시점까지 유지돼요.

## 면접 질문

**Q.** 쿠키와 세션의 차이점에 대해 설명하고, 각각 어떤 상황에서 활용되는지 말씀해 주세요.

**모범 답변**

쿠키와 세션은 무상태성을 가진 HTTP 프로토콜에서 상태 정보를 유지하기 위해 사용됩니다. 가장 큰 차이는 저장 위치로, 쿠키는 클라이언트 브라우저에 텍스트로 저장되는 반면 세션은 서버의 자원에 저장되고 클라이언트에는 세션 ID만 전달됩니다. 보안성 면에서는 중요한 데이터를 서버에 두는 세션이 더 유리하며, 쿠키는 개당 4KB의 크기 제한과 매 요청마다 서버로 전송되는 특징이 있습니다. 따라서 사용자 테마 설정이나 언어 선호도 같은 비인가 데이터는 쿠키를 활용하고, 로그인 인증 정보처럼 보안이 중요한 데이터는 세션을 활용합니다.

## 꼬리 질문

- **Q.** 쿠키의 만료 시간은 어떻게 설정하며, 만료 시간을 지정하지 않으면 어떻게 되나요?
  - Set-Cookie 헤더에서 Expires나 Max-Age 속성을 지정해 만료 시점을 설정해요. 속성을 설정하지 않으면 브라우저 세션이 끝날 때 삭제되는 세션 쿠키가 돼요.
- **Q.** 쿠키를 일반적인 클라이언트 데이터 저장소로 사용할 때 발생하는 단점은 무엇인가요?
  - 쿠키는 모든 HTTP 요청마다 서버로 자동 전송되어 네트워크 대역폭을 낭비하고 성능을 저하시킬 수 있어요. 따라서 단순 데이터 저장 목적이라면 웹 스토리지 API 사용이 권장돼요.

## 필기 대비 확인 문제

**1. 쿠키(Cookie)와 세션(Session)에 대한 설명으로 올바르지 않은 것은 무엇인가요?**

① 쿠키는 매 HTTP 요청 시 전송되므로 크기가 크면 네트워크 성능을 떨어뜨릴 수 있다.  
② 세션은 서버의 메모리나 데이터베이스에 데이터를 저장하므로 물리적인 서버 자원에 따른 용량 제한이 존재한다.  
③ Set-Cookie 응답 헤더에서 Max-Age 속성을 0으로 설정하면 해당 쿠키는 브라우저에서 즉시 삭제된다.  
④ Expires나 Max-Age 속성이 없는 쿠키는 브라우저가 종료되어도 삭제되지 않고 영구적으로 보관된다.  

> 정답: ④. Expires나 Max-Age 속성이 지정되지 않은 쿠키는 '세션 쿠키'로 동작하며, 브라우저 세션이 종료될 때 자동으로 삭제돼요. 영구적으로 보관하려면 만료 날짜나 기간을 명시해야 해요.
